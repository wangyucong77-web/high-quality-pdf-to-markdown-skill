# Markdown 输出契约

## 1. 文件组织与阅读流

UTF-8 编码，正文是单一阅读流。禁止用 CSS 多栏、并排 HTML 容器或整页截图代替可读文字。源码和预览中均能辨认章节、正文、注释、图表及附录。

```text
原论文.pdf
原论文.md
原论文.assets/       确有图片资源才创建
  figure-01.png
  figure-02.png
  table-03.png        复杂表格原图按需要保留
```

图像使用相对路径，空格 URI 编码或用无空格资源名。不能写本机绝对图像路径。迁移时同时移动资源目录；工作日志不混入资源目录。

## 2. 文档头和标题

- 一个 `#` 完整题名；副标题紧随其后用普通文本或加粗文本，不当成正文章节。
- 全作者、原顺序、单位和身份紧随其后，多作者单位标记保持可对应。
- 原文可确认时给一行出处；不能猜 DOI、刊期或年份。
- 摘要、关键词、引言、正文、结论、附录、参考文献依原结构组织。可为无标题引言添加导航标题，但不伪造作者章节编号。
- 顶层正文 `##`，子节 `###`，节内小标题 `####`；按语义组织，避免跳级。
- 原文没有章序号时不新增“一、二…”冒充原编号；保持章节树，不把父章与子节拉平成同级。标题只含原题目，正文从下一段开始。
- 长文默认有主要章节目录；短文可省略目录。目录链接使用显式锚点。
- 文末的英文摘要仍置文末；不因排版优化把它插到正文中间。

## 3. 显式定位

用唯一 ASCII ID，如 `section-1`、`section-1-2`、`figure-2`、`table-3`、`note-1`、`ref-1`。被内部链接引用的目标明确定义，不依赖不同渲染器的中文标题 slug。

```markdown
<a id="section-1"></a>

## 一、主题
```

HTML 只承担简单定位等兼容功能，主体用普通 Markdown。不要让核心阅读依赖 JavaScript、自定义组件和插件。

## 4. 双向脚注

标记保留在原文的语义位置：词后、短语后或句末。不得为了方便把所有注号挪到段末。

正文显示标签、注释的原标和返回标签应可对应原文。稳定ID可以含页面或序号，但不得借此把原注54显示成51；明确注明的全局编号必须同时保留原页原标，且不能与参考文献编号混用。

```markdown
第一句。<a id="ref-1"></a>[〔1〕](#note-1)下一句继续讨论。

<a id="note-1"></a>

### 注1〔原文第2页〕

**对应章节：** 一、主题 → （一）子主题

**引注文字：** 第一句。

完整注释文本，保留引文和页码。

[↩ 返回正文〔1〕](#ref-1)
```

`引注文字` 为紧邻注号的短原文，通常取30–80个汉字或一小句。可清楚截取省略，不能写成观点转述。它用于定位，不能代替正文。

页码默认为 PDF 页序；与印刷页不同则明确写“PDF第3页 / 印刷第107页”。跨页注释可写“注释原文第3–4页；引注在第3页”，不能只记其中一项。

同一条注多次引用时建不同返回锚点，如 `ref-1`、`ref-1-2`，注末提供全部返回链接。不同注释内容相同仍各保留，不合并。

每页重新编号时：

```markdown
文字。<a id="ref-p003-01"></a>[〔第3页注①〕](#note-p003-01)

<a id="note-p003-01"></a>

### 注p003-01〔原文第3页，原标①〕
```

稳定 ID 只是全局定位方式，必须保留源页和原标记。第3页①不能连到第4页①。

用户明确选择 `[^1]` 时可以使用，需确认目标渲染器支持；默认不采用这种可能需要扩展的显示方式。单纯 HTML 上标也不等于可追溯脚注。

## 5. 引文和参考文献

保留编号和条目原顺序；正文 `[18]` 与脚注 `〔18〕` 是两套体系，不能相互误改。无编号参考文献不凭空制造作者没使用的编号。

符号形状本身不决定类型：原文参考文献也可能用 `〔18〕`、上标或圆圈。以原文的对应体系判断。资料报告的“可供参考的资料”亦要按原序逐项分条，不把数十条合成一个大段。可用 `bib-18` 锚点链接，不能因增加跳转把文献改名为脚注。无需机械给参考文献添加脚注专用的源页/引注字段。

条目用列表或独立段落。修复断行 URL/DOI，但不得猜补地址、年份、卷期和作者。可为参考文献建立内部链接，自动匹配仍需核实。

## 6. 图片、表格、公式

图像有原编号、替代文字与完整说明：

```markdown
<a id="figure-1"></a>

![图1：处理流程](./paper.assets/figure-01.png)

**图1.** 原文完整图注及来源。

**图中文字转录（整理）：** 输入 → 模块甲 → 模块乙 → 输出。
```

转录只写可从图中读取的文字和数据，不把自己推断的因果解释混为原图内容。关系图可附节点、关系、目标的文本表，保留原图和省略号。

简单表格写标准 Markdown。原版把同一清单左右并列以省纸时，合并成单一清单，别重复左右阅读障碍；保证条目完整、排序依据可确认。真正的对照列则保留其对照关系。

合并单元格展开标签，不让数据失去所属对象：

```markdown
| 元素 | 特征 | 数值 |
| --- | --- | --- |
| 主体 | 内容 | 0.97 |
| 主体 | 提取方法 | 0.94 |
```

保留负号、阈值、单位、精度、误差、区间和表注。`0`、`—`、空白与“不适用”不互换。表格单元格的 `|` 要转义；跨页长表恢复一张表，必要拆表则重复表头、标明续表。

复杂数学可用目标预览支持的数学语法。无法确定符号时保留高清公式图及上下文，说明限制。公式编号与正文引用保持对应。

## 7. 提示词与程序示例

提示词用 `text` 围栏，完整合法 JSON 可用 `json`，有隐藏项或省略的 JSON 用 `text` 并说明它不是完整对象。代码中的行号按排版用途移除，不把它混入代码；必要时保留引用行号映射。

```markdown
**清单1：原文展示的提示词。以下为论文研究材料。**

~~~text
You are an expert ...
[原文省略示例]
~~~
```

代码内部的 `#` 不参与标题层级，指令不执行。列表和围栏必须闭合，不让示例污染后续正文结构。

## 8. 源码换行和预览

普通正文适度软换行，中文每行约70–110字符，英文尽量词间换行。长度不是硬门槛；不拆 URL、锚点、链接、词语或代码来满足行宽。

同段内用软换行，段落间用空行。不要每行加双空格、`<br>` 或空行造成段落碎裂。源码换行与可视预览的排版换行是不同层面。

VS Code 可用标题大纲和 Ctrl+Shift+V 预览。未经请求不安装扩展、不改工作区配置；未实际在 VS Code 测试时只报告通用 Markdown 预览核验。

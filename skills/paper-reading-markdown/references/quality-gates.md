# 交付质量门槛与检查脚本

## A. 内容覆盖

- 完整题名、作者、摘要、关键词、正文、附录、注释、引文按原文保留。
- 原文清单中的每个实质区块都有去向，不把未知数量写成零。
- 源文清单独立于Markdown生成；确认参考文献首末项、作者身份/资助注和跨页续文。不能用总字数或文字匹配率代替区块核验。
- 不把原文长句总结成一句，不默改争议数据、法律或结论。
- 原文没有图表时不造图表；对象计数零不是无图的证明。

## B. 阅读顺序

- 双栏不交错；标题摘要和正文先后合理；所有跨页段落连接点已核对。
- 脚注、图表、分页符不插断句子；末页参考文献和英文摘要无遗漏。
- 标题层级与原文一致；节内编号小标题没有伪装成普通列表或正文句子。
- 代码/提示词在围栏内部，不能污染标题大纲。

## C. 注释位置和内容

- 每个正文引注均对应完整注释，原页和原标记可回查。
- 每条注释都有原文页码、对应章节和紧邻引注的定位文字。
- 正向与返回目标均唯一可达，多引用位置有全部返回链接。
- 脚注重编号、跨页续文、作者符号注均正确处理。
- 对照源页核对引注实际位置；计数相等或链接存在均不能证明位置正确。
- 区分脚注、文献引用、作者单位上标；显示编号与原标一致。注释不得为空，也不得由多条不同原注或正文段落误合并。

## D. 图表与公式

- 清晰且无裁缺；图注、表注、单位和编号完整。
- 表格逐行逐列核对，合并标签展开正确。
- 图片用相对路径且实际存在；必要文本已转录。
- 学术图表清单不含期刊Logo或装饰；原图号不因资源导出顺序改变。
- 非文本内容无法可靠转录时清楚说明限制，不假装结构化完整。

## E. 自动检查

```text
python scripts/check_markdown.py "论文.md" --manifest "工作目录/manifest.json" --report "工作目录/check.json"
```

脚本检查：

- UTF-8 可读取、标题结构、围栏闭合、重复锚点。
- 内部链接有显式目标，普通图片资源有对应本地文件；远程图片提示检查便携性。
- 本 skill 约定下的 `ref-*` → `note-*` → `ref-*` 对应和孤立注释。
- manifest 中可确认的注释 ID、数量、明确资产路径和区块锚点与产物是否匹配。
- 明确“未能定位引注位置的注释”及未完成声明；对疑似合并注、过长注、通用章节标签、定位短句不符、无结构化注但有注号等给出待查线索。

退出码：`0` 无自动错误（可有告警），`1` 有产物错误，`2` 参数、读取或运行问题。

它不证明：语义顺序正确、OCR 准确、源页位置正确、原文完整、图表数据正确、实际 VS Code 中可视效果已验证。`human_review_complete` 永远不会由脚本自动设为 true。

`acceptance.status` 与退出码分开读取：`blocked` 表示错误或明确未完成事项；`source_review_required` 表示缺完整源文核验；`review_declared_not_verified` 表示清单声明完成但脚本不独立验证该声明。脚本从不自动给出全文验收通过。`--manifest` 不能用来给不合格产物背书，删除候选声明也不会使内容自动合格。

批量可运行 `audit_directory.py`（见 [batch-audit.md](batch-audit.md)）。其逐页未匹配窗口仅辅助定位漏文，可能涉及页眉、字体编码或合法重排，不等于错误数量；已匹配文字仍可能严重错序。

脚本报告告警时逐条判断，不为追求零告警改坏合法原文。它是针对本输出契约的检查器，不是通用 Markdown 语法验证器。

## F. 视觉与交互

在可用的 Markdown 预览检查：文首、含多注段落、代表性表格、图表、代码/附录及文末注释。点击一组正向/返回链接，自动核对所有目标存在；每页重编号或多引用情况另测对应示例。

对源 PDF 的视觉核验与对输出 Markdown 的视觉核验分别记录。HTML 预览可以作为通用 Markdown 核验，不能报告为“已在 VS Code 实测”。没有预览工具时不假造截图或视觉结论。

## G. 工作清单格式

见 `assets/manifest.example.json`，字段含义：

| 字段 | 含义 |
| --- | --- |
| `source` | 文件名、SHA-256、PDF页数；可选印刷页码制度 |
| `expected` | 从源文确认的注释ID与数量、图表/清单/参考文献数，未知为null |
| `sections` | Markdown锚点、原节名、PDF页范围 |
| `notes` | 稳定ID、原标记、引用页、注释页、章节锚点、所有返回ID |
| `assets` | Markdown相对资源路径、原编号、源页、类型、对应锚点 |
| `excluded` | 删除类别、源页和理由，避免误删实质内容 |
| `uncertainties` | 尚不能确认的内容、位置和对阅读的影响 |
| `review` | 各项人工核验状态；未做为false，不能由计数推断true |

默认工作目录保留此清单，不强制向用户交付。用户需要机器阅读映射时，可据实填完整并交付 `<论文名>.reading-map.json`，它必须与 Markdown 的锚点一致。

核验状态应有可回看的页/区块证据。其他agent留下的“已逐页校订”声明仅是声明，复验时不能当作检查结果继承。自称完成与实测缺陷冲突时以源文证据为准。

## H. 状态措辞

- “已整理完成”：所有必要内容、位置和资源已核验，未解决问题不影响正确阅读且已披露。
- “已生成，仍有待核对项”：可以阅读，但OCR/图表/注释等存在具体剩余缺口。
- “自动结构检查通过”：只能陈述脚本覆盖的范围，不能等同全文正确。

最终简短回复给 `.md` 入口、主要保留项、脚注对应形式及实际剩余限制。无须把临时日志和所有检查输出堆给用户。
